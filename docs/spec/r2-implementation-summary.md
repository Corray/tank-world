# R2 实现总结（L2）

**日期：** 2026-06-04 / **分支：** feature/r2-progression / **关联：** PRD R2（accepted）、共识 v2、数据模型 §10~16

## 背景

R2 主题「从 demo 到游戏」：修复 MVP 验收实证的难度失衡 + 补重玩动机。范围 P0+P1 全量（难度平衡 / 三关卡 / 道具×3 / 最高分存档）。

## 做了什么

按数据模型 §16 切片 Q1~Q6：

- **Q1 关卡推进**：GameState 拆 LEVEL_CLEAR / GAME_COMPLETE；判定时即时入账（score → bankedScore）；DEFEAT-R 改为当前关重试（六字段重置）
- **Q2 三关内容**：LEVELS 配置表（构成/间隔/布局）；出生序列改按构成轮转生成；三张地图均含双层砖护圈，玩家出生点移至 (12,2)
- **Q3 AI 分层**：`decideDirection` 单决策缝——FAST 50% 压基地 / ARMORED 50% 压玩家 / BASIC 均匀随机；射击间隔 1200→1800ms
- **Q4 道具链路**：携带者（出生位 4/8/12）→ 死亡掉落（固定循环）→ 玩家专属拾取（C13）→ 三效果（护盾刷新制 / 双发动态上限 / 炸弹无分清场）
- **Q5 视觉**：S/F/B 贴片、携带者金色闪烁、护盾青环、HUD 关卡 + 两档最高分
- **Q6 平衡探测**：被动存活 5 局 [22,71,60,51,23]s（MVP 基线 ~10s）；默认参数即轮次 1，未触发调参

## 关键决策与思考

1. **入账时机放在 judge 而非 advanceLevel**——过关瞬间分数语义就确定（最高分提交同帧），间奏画面只读展示，避免「停在过关画面时分数悬空」
2. **重试 = loadLevel 复用 + 三行显式重置**（score/lives/doubleFire），与「过关保留 doubleFire」共用同一 loadLevel 而语义不串——靠调用方显式表达差异，loadLevel 自身保持无立场
3. **AI 单决策缝 `decideDirection`**：偏置逻辑收口为一个可统计测试的纯决策函数，统计断言（200 次 ∈[40%,75%]）替代锁定单次随机
4. **炸弹在 combat 前结算**（管线顺序 player→powerup→spawn→enemy→combat）：被炸死的敌人当帧即出局，杜绝子弹双重计分（风险 §15 的结构解）
5. **storage 失败静默降级**：try/catch 全包，隐私模式下游戏完全可玩只丢持久化

## 模块结构增量

```
level/   → LEVELS 配置 + 序列生成 + loadLevel/advanceLevel/retryLevel
powerup/ → 掉落循环 + 拾取判定(C13) + 三效果
storage/ → 两档最高分（比较写入 + 静默降级）
```
