## 1. 问题陈述

1. **计分单调**：每个敌人固定分值，无「连续击杀」激励，高分玩法缺节奏维度。
2. **连击 = 替「炸弹不计分」的正向激励**：奖励玩家在时间窗内连续枪杀（与炸弹清场零分形成对照）。
3. **收尾 5d32**：R14 审计遗留的 update.ts 头注释过时（deferred 三轮），本轮触 update.ts 顺带清。

## 2. 需求清单

### F-R18-1 连击状态（P0）

- `World` 增 `comboCount: number`（当前连击数）、`comboUntil: number`（下次击杀延续连击的 game-clock 截止，0=无连击）
- `constants`：`COMBO_WINDOW_MS`〔默认 3000〕、`COMBO_STEP`〔默认 0.1〕、`COMBO_CAP`〔默认 9〕

### F-R18-2 连击倍率计分（P0）

- 敌人击杀（combat C5，hp≤0）时：
  - `comboCount = world.clock < world.comboUntil ? comboCount + 1 : 1`；`comboUntil = clock + COMBO_WINDOW_MS`
  - `mult = 1 + COMBO_STEP × min(comboCount - 1, COMBO_CAP)`（首杀 comboCount=1 → mult=1，**单杀零回归**；连击封顶 ×2）
  - `awarded = round(hit.score × mult)`；`world.score += awarded`、`killer.score += awarded`、飘字显示 awarded
- **单杀不变**：首杀 mult=1 → 既有单杀计分测试零回归（设计保证）

### F-R18-3 连击重置（P0）

- 玩家死亡（damagePlayer）→ `comboCount=0, comboUntil=0`（streak 断）
- loadLevel（过关/无尽换关）→ 重置（新关清零，避免冻结间奏期 stale combo）
- 时间窗过期 → 下次击杀 lazy 重置为 1（无需 active tick）

### F-R18-4 HUD 显示（P1）

- 连击激活时（`clock < comboUntil` 且 comboCount≥2）HUD 显示 `COMBO ×N`；过期/无连击不显示

### F-R18-5 技术债收尾（P0）

- F-ARCH-5d32：update.ts 头注释引用 v1 旧管线 → 更新为当前管线（含 powerups/shovel/judge 路由）
