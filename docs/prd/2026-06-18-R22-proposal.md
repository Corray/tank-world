## 1. 问题陈述

唯一登记在案的真实技术债：combat ↔ player 运行时循环依赖。靠 ESM 函数提升运行无误，但依赖图有环（初始化顺序脆弱 + 分层不清）。R14 审计 deferred 代码重构待独立 ADR——本轮做（ADR-004）。

## 2. 需求清单

### F-R22-1 damagePlayer 归位 combat（P0，纯重构）

- `damagePlayer` 从 player.ts **逐字移到 combat.ts**（函数体零改）；combat 删 `import damagePlayer from player`
- import 两侧对账：combat 增 INVINCIBLE_MS/flashPlayer/Direction(值)/EXPLOSION_COLOR_PLAYER；player 删随之孤立的 Direction/INVINCIBLE_MS/effects/audio 导入
- 8 处导入者（update.ts + 7 测试）re-point `damagePlayer` player→combat

### F-R22-2 依赖无环不变量（P0，重构交付物）

- 新增不变量测试：combat.ts 源码不含 `from '../player'`（机器可验循环已拆）
- 行为零变更：既有 321 测试全绿即证（damagePlayer 体不变）

## 3. 明确不做（本轮）

- 任何行为/功能变更（纯依赖治理重构）
- 其他模块依赖重排（仅拆这一个环）
- moveTank/firePlayerBullet 迁移（它们是 combat 物理核心，player→combat 单向边保留）

## 4. 成功指标

- combat 不再 import player（依赖无环不变量绿）；player→combat 单向
- 既有 321 测试零回归（行为零变更）；tsc 净；ADR-004 落档
