## 1. 问题陈述

1. **玩法维度缺口**：R8 是纯 PvP（无 NPC）。「混战」= 在对战中叠加 NPC 第三方威胁，是经典坦克大战最混乱的形态（守家 + 互射 + 躲 NPC 三件事并行），R8 PRD §3 明确标为「叠两套胜负逻辑」推迟到 R9。
2. **首个「三方」模式**：MELEE 是首个 **PvE + PvP 同时激活** 的模式（此前要么纯 PvE，要么 R8 纯 PvP）。混合判定可能有未预见交互——写入点级方法第 4 轮压测维度。
3. **方法自洽窗口**：dogfood 增量 5（提交 standard #33）提出「分叉清单判据应为逻辑写入点数、锚决策点」——R9 正好按该细化跑一遍，给 #33 闭环实证。

## 2. 需求清单

### F-R9-1 MELEE 模式入口（P0）

- `GameMode` 增 `MELEE` 值；READY 按 **4** 进入；按 1/其余=SOLO、2=COOP、3=VERSUS 零回归
- 输入双键位复用 COOP/VERSUS 映射（P1 WASD+J / P2 方向+Enter）

### F-R9-2 NPC 第三方（P0）

- MELEE 竞技场 `enemyTotal>0`，NPC 持续出生（复用 enemy 模块 + spawnSequence）
- NPC 从**中立侧边点**出生〔默认 (6,1)/(6,11)，VS 竞技场空地、等距双基地〕——不偏袒任一方（不用顶行 NPC 点：那是 P2 侧+基地格）
- NPC AI 威胁双玩家（C6′ 敌弹伤任一玩家）+ 双基地（NPC 子弹可毁任一基地）；ARMORED 偏好最近存活玩家（复用 §3.9）

### F-R9-3 胜负规则（P0，OPEN-R9-1 决议=强化对战）

- **沿用 R8 双条件胜负**：摧毁对方基地 **或** 打光对方命数（各 3 命）→ 对方负，先达者胜该局
- **NPC 毁某座基地 = 该基地所有方负**（不论毁因是对手还是 NPC——`versusBaseDown(side)` 已与毁因无关，零改判）
- **比分不决胜负**（强化对战）：NPC 击杀 per-player 计分仅 HUD 显示/炫耀，胜负纯由基地/命数定

### F-R9-4 NPC 计分（P0）

- NPC 击杀按 §3.3 分值，per-player 归属（复用 C5 `bullet.playerId`）；HUD 双方分数并显

### F-R9-5 道具（P1，OPEN-R9-2 决议=NPC 携带者复活）

- 恢复 §3.8 携带者机制：每局第 4/8/12 个出生 NPC 携带、死亡掉落（复用 `dropFromCarrier`）
- 三道具全开（护盾/双发个人化 + **炸弹**）；MELEE 炸弹语义 = 清场上全部 NPC（复用既有 `for e of enemies`，不伤玩家）——清场 = 否定对手 NPC 分 + 解威胁

### F-R9-6 回合制（P1，OPEN-R9-3 决议=best-of-3）

- 沿用 R8 best-of-3（先胜 2 局）；每局间场复用 VERSUS_ROUND；每局开始双方满命、地图/道具/**NPC 池**全重置

### F-R9-7 写入点级分叉清单 v4（P0 方法载体，G3 产物）

- 产出「模式分叉清单 v4」：grep **决策点**（`=== GameMode.MELEE`/`isPvP`/`case` 分支头）而非全 token
- **采纳 dogfood 增量 5 判据细化**：清单行数 = **逻辑写入点数**（一点多引用按一行算），机器核验锚决策点——给 #33 HIGH-1 边界补丁闭环

## 3. 明确不做（本轮）

- **比分混战·去基地**（OPEN-R9-1 选项 b）：抛弃 R8 双基地建模，方向已选强化对战
- **NPC 结盟/互斗**：经典 NPC 中立威胁，AI 复杂度不成比例
- **成就接入 MELEE**：同 R8，8 成就语义与对抗阵营不兼容
- 战役新关卡 / 随机地图 / 移动端 / 联机 / 编辑器

## 4. 成功指标

- MELEE 全链路绿：入口→NPC 出生→三方交战→双条件胜负（含 NPC 毁基地）→best-of-3→结算
- **SOLO/COOP/VERSUS 行为零回归**（MELEE 是纯增量；R8 的 210 测试不许变红）
- 友军火力 + NPC 计分 + NPC 毁基地归属三态正确
- 分叉清单 v4 按「逻辑写入点数/锚决策点」判据（增量 5 自洽实证）
