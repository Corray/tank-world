## 1. 问题陈述

1. **战役偏短**：3 关一通即入无尽，战役叙事弧度浅。扩至 5 关。
2. **方法核心价值——基础常量 blast radius**：`LEVEL_COUNT` 是被 8 处 src 派生、~10 个测试文件硬编码的地基常量。3→5 是检验「常量派生 vs 硬编码」家族 + 影响面方法（spec-to-code-flow 影响面 checklist）的最强样本。
3. **暴露硬编码债**：`enterEndless` 写死 loadLevel(4)、`variantLayout` 写死 `level-4`、`endlessConfig` 写死 `level-3`——均应 LEVEL_COUNT 派生。本轮一并修正。

## 2. 需求清单

### F-R17-1 LEVEL_COUNT 3→5 + 两新关卡（P0）

- `LEVEL_COUNT` 3→5；`LEVELS` 数组 +L4_LAYOUT/L5_LAYOUT 两配置
- 难度延续递进〔默认〕：L4=22 敌（7/7/8）间隔 1800ms；L5=26 敌（8/9/9）间隔 1600ms
- 两新 13×13 布局：基地 (12,6) + 砖护圈、出生点 (0,0)/(0,6)/(0,12) 清空、玩家 (12,2)、各含 ≥1 草/水/冰（AC-35 延续）

### F-R17-2 硬编码债修正（P0，blast radius 核心）

- `enterEndless` loadLevel(4) → loadLevel(**LEVEL_COUNT+1**)（无尽起点随战役长度）
- `variantLayout` baseIdx `(level-4)` → `(level - LEVEL_COUNT - 1)`（首个无尽关派生）
- `endlessConfig` k `(level-3)` → `(level - LEVEL_COUNT)`（无尽深度派生）

### F-R17-3 自动派生项零改（P0，验证派生正确性）

以下 8 处 src 用 `LEVEL_COUNT` 表达，扩展后**自动跟随，零改**：update.ts 无尽判定/GAME_COMPLETE 触发、level.ts isBossLevel 终点+里程碑+boss idx、achievements FULL_CLEAR、hud 关卡显示。这是「常量派生」的红利——本轮验证它们确实零改。

### F-R17-4 里程碑语义随之平移（P0）

- 战役终点 boss：L3→**L5**
- 无尽 boss 里程碑：L8/L13/L18 → **L10/L15/L20**（首个无尽关 L6 起，每 5 关）
- 三循环轮换序数不变：L5/L10=idx1 BOSS，L15=idx2 SUMMONER，L20=idx3 GUARDIAN
- `ENDLESS_8`（Endless Eight 成就）**保持字面 level≥8**（名称绑定数字 8，不派生；副作用=略易达成，已知接受）

## 3. 明确不做（本轮）

- 战役 >5 关（5 关够弧度）
- 无尽公式重构（仅修硬编码债，曲线不变）
- 新地形类型 / 新机制（纯关卡数据扩展）
- ENDLESS_8 阈值派生（保字面 8，名称优先）

## 4. 成功指标

- 战役 5 关可通，L5 终点 GAME_COMPLETE，无尽从 L6 起
- 8 处 LEVEL_COUNT 派生项零改（验证派生红利）；3 处硬编码债修正
- 里程碑平移正确（L5/L10/L15/L20）
- **基线冲击全部在 G3 预判清单内**（~10 测试文件 churn，这是 blast radius 方法的核心交付——预测每一处而非事后补）；tsc 净
