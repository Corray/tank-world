## 1. 问题陈述（实验场视角）

四轮迭代压测过的流程维度：全链路 spec 节点、4 道门禁、骨架锁定、基线修订纪律、纯增量模块扩展。**尚未压测的维度**：
1. **破坏单数假设的结构性重构**——`world.player` 单实体假设遍布 player/combat/render/hud/judge，本地双人会冲击碰撞矩阵 3 行（C6/C11/C13）、重生/计分/道具归属全链路——这是对 spec-to-code-flow 承载大重构能力的真实考验
2. **CI/发布管道**——项目至今零 CI；测试门禁进 CI + Pages 自动发布，顺带实践此前 FB（conflict-marker-guard-gap）提出的「机器防线」主张

## 2. 需求清单

### F-R5-1 本地双人合作模式（P0，实验主菜）

**玩法（经典 Battle City 双人制式草案）**：
- READY 画面选 1P / 2P（按 1 / 2 键）；2P 模式：P1 = WASD + J，P2 = 方向键 + Enter
- 合作共守基地：命数各自 3，得分各自累计 + 结算显合计；一人命尽另一人继续，**双双命尽或基地毁才败**
- 道具谁捡谁得；玩家间互相阻挡不伤害（C11 语义扩展）；敌方子弹对两玩家均有效（C6 扩展）
- 最高分档位：双人模式单设 `best-coop`〔默认〕，不与单人档混淆
- `[OPEN-R5-1]` 成就在 2P 局的处置：禁用 vs 照常全局判
- `[OPEN-R5-2]` 无尽模式是否开放 2P：首版建议仅 L1~L3 + GAME_COMPLETE（无尽留后续）

**实验观测点**（写给流程，不写给玩家）：单数→复数重构下，骨架锁定的基线修订量级、碰撞矩阵文档与代码的同步成本、门禁对结构性改动的预判准确率。

### F-R5-2 CI + GitHub Pages 发布（P1）

- 仓库转 public（已拍板）
- GitHub Actions：PR → `tsc --noEmit` + `vitest run` 门禁；master push → build + 部署 Pages
- README（截图 + 玩法 + 一行架构说明 + agent-dev-standard 工作流声明与 spec 文档指引——作为工作流公开案例）

## 3. 明确不做（本轮）

联机 / 移动端 / 编辑器 / 随机地图 / 音效采样路线（耳测已随验证债 dismissed，合成音效定稿）。

## 4. 成功指标（实验场口径）

- 双人全链路绿（骨架先行 + 回归 147 块的存活率即重构冲击的量化数据）
- 基线修订全部留痕且每处有 spec 依据（修订量本身就是 dogfood 数据）
- PR 门禁 CI 跑通 + Pages 链接可玩
- 本轮结束补一份 dogfood 报告增量（单数→复数重构样本）反哺 standard
