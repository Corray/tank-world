## 1. 问题陈述

1. **Boss 单一化**：无尽/波次长跑里每个里程碑都是同一个 BOSS，记忆点衰减。
2. **召唤机制 = 新威胁维度**：BOSS 是火力型（弹幕），SUMMONER 是消耗型（增援）——迫使玩家在「斩首」与「清兵」间做战术选择。
3. **方法第四证**：EnemyType 再扩 = 穷举映射家族第四次自我应用（R10 事后拦→R11 预补→R12 1:1→R15 验证稳定性）。

## 2. 需求清单

### F-R15-1 SUMMONER 敌型（P0）

- `EnemyType` 增 `SUMMONER`：HP **6**〔默认〕、分 **800**〔默认〕、基准速度、同 TANK_SIZE
- 穷举映射全扫：ENEMY_HP / ENEMY_SCORE / render COLOR.enemy +SUMMONER 项
- 新锚 `isBossType(t) = BOSS || SUMMONER`（isPvP 同款单一判定锚）：HP 条渲染 + Boss 系 AI 路由共用

### F-R15-2 召唤机制（P0，OPEN-R15-3 决议=须清完）

- SUMMONER 每 `SUMMON_MS`〔默认 4s〕在自身邻近空位（tankAreaFree）召唤 1 个 BASIC
- 同屏存活 ≥ ENEMY_CONCURRENT 时跳过本次召唤（复用既有上限）
- 召唤兵 push 进 enemies，**不动 spawnedCount/enemyTotal** → fieldClear 天然要求清完（零新胜负逻辑，R11 同款红利）；SUMMONER 死即停止召唤（AI 随 alive 终止，涌现）
- **狂暴（HP≤50%）**：召唤加速 `SUMMON_RAGE_MS`〔默认 2s〕；**不**三向弹幕（与 BOSS 差异化）；常规射击保持单发周期

### F-R15-3 里程碑轮换（P0，OPEN-R15-2 决议=按序交替）

- `bossTypeFor(milestoneIdx)`：奇数→BOSS，偶数→SUMMONER（确定性，无随机）
- 战役 L3 恒 BOSS（idx 恒 1）；无尽 L8=1/L13=2/…；波次 wave5=1/wave10=2/…
- loadLevel / applyWave 注入处由 `EnemyType.BOSS` 改 `bossTypeFor(idx)`

### F-R15-4 HP 调参搭车（P1，OPEN-R15-4 决议）

- `BOSS_HP` 10→**8**（R11 僵持体验债）；SUMMONER=6 同步定标
- G3 预扫数值断言族：T-BOSS-* 全用常量引用（跟随变化）——预判零基线修订

## 3. 明确不做（本轮）

- 大体型 2×2 碰撞盒 / Boss 掉道具 / 第 9 成就 / Boss UI 横幅（矩阵 B5~B8 丢弃理由）
- 召唤兵种类多样化（恒 BASIC，控变量）
